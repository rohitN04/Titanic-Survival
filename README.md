# Titanic Survival Prediction — Machine Learning Modeling

Predicting passenger survival on the Titanic using classification models (Logistic Regression, Decision Tree, Random Forest) with a leakage-safe sklearn Pipeline workflow.

## Dataset

[Kaggle Titanic Dataset](https://www.kaggle.com/datasets/shuofxz/titanic-machine-learning-from-disaster)
- **Training set**: 891 passengers, 12 features, labeled
- **Test set**: 418 passengers, 11 features, unlabeled (for final submission)

## How to Run

### Option 1: Google Colab (Recommended for notebook)
1. Upload `Titanic_Project_v3.ipynb` to [Google Colab](https://colab.research.google.com/)
2. Run all cells (Runtime → Run all)
3. The notebook downloads the dataset automatically via `kagglehub`

### Option 2: Modular Pipeline (CLI)
```bash
pip install -r src/requirements.txt
python -m src.main
```
This executes the full pipeline: data loading → EDA → feature engineering → model training → evaluation → predictions → model saving.

### Option 3: Inference on New Data
```bash
python -m src.predict --model src/model.pkl --input new_data.csv --output predictions.csv
```

## ML Workflow

1. **Load** train and test datasets from Kaggle
2. **Explore** data distributions, missing values, correlations
3. **Train/Test split** (80/20 stratified) — done **before** any imputation or feature engineering
4. **Feature engineering** (row-local only — applied independently to train, validation, and test sets)
   - Title extraction, FamilySize, IsAlone, FarePerPerson, FareGroup, AgeGroup, TicketFreq
5. **Pipeline** handles imputation (Age → median, Embarked → mode), scaling, and encoding — fitted only on training data
6. **GridSearchCV** with 5-fold CV for hyperparameter tuning
7. **Evaluate** with Accuracy, Precision, Recall, F1, ROC-AUC, 10-fold CV
8. **Visualization**: Confusion matrices, ROC curves, overfitting analysis, feature importance, key findings
9. **Final predictions** on Kaggle's unseen test set (`test.csv`)

## Limitations

1. **Small dataset** (891 training samples) — limits model complexity and generalization
2. **Missing Age** (~20%) imputed with median — may not capture true distribution
3. **Cabin dropped** (77% missing) — deck letter could have been a useful feature
4. **No ensemble/stacking** methods attempted beyond Random Forest
5. **Class imbalance** (~38% survived) — not explicitly addressed with SMOTE or class weighting
6. **Limited hyperparameter search** — wider grids or Bayesian optimization could improve results
7. **Row-local feature engineering only** — ticket group frequency is computed per-split, not across the full dataset, which may reduce its effectiveness
